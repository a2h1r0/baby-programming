## 起動と画面

- [ ] ZIPを展開し、`index.html` をPC内に保存した。
- [ ] 保存したファイルをダブルクリック、または「プログラムから開く」でChrome／Firefoxを選び、起動できた。
- [ ] アドレスが `file:///.../index.html` で始まっている。
- [ ] 2つの大きなモード選択ボタンが表示された。
- [ ] 1024×768・ブラウザー倍率100%で、ハチ、お花、命令一覧、命令ボタン、GO、やりなおすが1画面に収まった。
- [ ] スクロールせずにすべての主要操作ができた。OSの表示倍率を上げて使う場合も、実際の授業設定で画面を確認した。
- [ ] ハチの顔の向きと、お花の位置が分かる。イラストやアイコンに欠けがない。
- [ ] 子どもの指でボタンを押しやすく、隣のボタンに触れにくい。設計上のタップ領域は64px以上だが、実際の画面サイズでも操作しやすい。

## 命令入力とタッチ

- [ ] 前進ボタンを1回タップすると、命令がちょうど1個追加された。
- [ ] タッチ後にマウス由来のイベントが重なって、同じ命令が2個追加されなかった。
- [ ] 連続でタップした回数と命令数が一致した。
- [ ] ボタンを押したときにページのスクロールや文字選択が起きなかった。
- [ ] 命令一覧の途中の1個をタップすると、その命令だけが消えた。
- [ ] 最後の命令を取り消すボタンで、末尾の1個だけが消えた。
- [ ] 12個まで入力でき、それ以上タップしても命令が増えなかった。
- [ ] マウスのクリックでも同じ操作ができた。
- [ ] 複数の指が偶然触れても、勝手なズーム、操作不能、意図しない連続実行が起きなかった。ブラウザーやタッチドライバーによる違いも記録した。

## 実行・成功・失敗

- [ ] かんたんモードの最初の課題で、前進1回とGOでお花に着いた。
- [ ] かんたんモードの2〜4マスの課題も正常に動いた。
- [ ] チャレンジモードを選び、前進・左回転・右回転が使えた。
- [ ] 前進はハチが向いている方向へ1マス進んだ。
- [ ] 左右の回転は90度で、その命令だけではマスを移動しなかった。
- [ ] 複数の命令を入力すると、表示した順番どおりに動いた。
- [ ] 実行中の命令が分かり、低スペックPCでも移動や回転を見分けられた。
- [ ] GOを連打しても、実行が重ならなかった。
- [ ] 実行中に命令ボタンや命令一覧を触っても、実行内容が途中で変わらなかった。
- [ ] 最後の命令でお花に着くと、大きな成功演出が表示された。
- [ ] お花に届かない、通り過ぎる、フィールドの外へ進もうとする場合に、成功にならなかった。
- [ ] 失敗後に命令が残り、一部を直してGOで再挑戦できた。ハチは課題の最初の位置から動いた。
- [ ] やりなおすで命令が全部消え、ハチが最初の位置に戻った。
- [ ] 成功後、同じ課題と次の課題を選べた。最後の課題の後も繰り返し遊べた。
- [ ] 音を消しても、操作・移動・結果を理解できた。

## オフライン・初期化

- [ ] Wi-Fiをオフにし、必要なら有線LANケーブルも外した。
- [ ] ネットワークが切れた状態でブラウザーを閉じ、`index.html` を開き直せた。
- [ ] オフラインで両モードの命令入力・実行・成功・失敗・再挑戦が動いた。
- [ ] ブラウザーを更新するとモード選択画面に戻り、古い命令や実行状態が残らなかった。
- [ ] 操作中にエラー表示や画面の停止がなかった。確認できる場合はブラウザーの開発者ツールでJavaScriptエラーも調べた。
